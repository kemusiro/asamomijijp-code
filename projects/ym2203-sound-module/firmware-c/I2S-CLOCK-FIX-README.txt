Rev C C0.5.0-alpha.4 / 待機中の音声fault5・次回BEGIN拒否の修正

確認した事実
  HOSTプレーヤーの一覧更新と選曲の後、BEGINがcode12/state5/error12/audio_ok=0で拒否されました。
  追加のRev CログはC0.5.0-alpha.3、fault=5、AUDIO blocks=212480、gates=0でした。
  以前のYs IIは123137/123137件を完了しています。音声エンジンは曲が終わっても動き続けるため、
  その後の異常を保持した状態では、新しいBEGINは受理しません。STOPだけで音声faultは解除しません。
  既存のYs II全曲受入結果は保存します。この後続異常がなかったことにはしません。

修正と限界
  I2S速度は外部FM時計に追従しますが、旧版は640ブロックごとの分周値を毎回整数へ丸めていました。
  1段階は150MHz時に約80ppmで、下位の余りが失われ続けると音声キューの位相が徐々にずれます。
  修正版は余りを次回へ繰り越し、平均の丸め誤差が蓄積しないようにします。
  再起動時は実際のPIO分周値も既定値へ戻します。音量、PCM変換、125→108、2ブロック/4.5msは維持します。
  実際のaudio.cを使い、RX/TXの独立した時計・DMA連鎖・分周値の量子化をモデル化したところ、
  旧版では+30ppmと+500ppmで約73～75秒後にfault5、-30ppmでは約432秒後にfault8を再現しました。
  修正版は±5、±30、±500ppmそれぞれ10分のモデル試験を完走しました。
  これは同じ異常コードを起こせるソフトウェア上の経路の確認です。旧実機にはDMA停止直前の記録がなく、
  今回の実機異常の内部タイミングまで確定したとは扱いません。
  実際のTX停止・キュー破綻・PCM異常を無視して継続する修正ではありません。

更新
  1. 両方の音量を下げ、HOSTを停止します。現在のfault5ログは保存済みです。
  2. Rev CをBOOTSELで起動し、このZIPのrevc-c.uf2を書き込みます。外部5Vは従来の手順を維持します。
     これにより旧fault5を保持した状態から再起動します。GPIOと配線は変更しません。
  3. CDCでSTATUS C=0.5.0-alpha.4、audio_ready=1、fault=0を確認します。
     既存のCDC/MIDI画面は対応しています。曲の自動再生はしません。
  4. 操作側Picoのライブラリ、player.py、/music/song.bin、recovery.binは既存のまま使用できます。
     プレーヤーの表示にTarget C0.5.0-alpha.3と出ても、それはHOSTの案内文です。
     実際のRev C版はCDCのSTATUSで確認します。I2C v2の形式に変更はありません。

最小の再確認
  ・player.pyの曲一覧を表示したまま、まず10分待機します。操作側やRev Cをリセットしません。
    再生終了後だけでなく、待機中にも同じ音声処理が動いています。旧ログの長い待機条件を確認します。
  ・CDCのaudio_ready=1/fault=0を確認し、recovery.binの番号を選んで13秒の診断を再生します。
    正常終了後もメニューへ戻り、再び番号を選んで演奏できることを確認してください。
  ・続いて必要に応じてsong.binでYs II、r 番号で単曲リピート、a/lで連続再生を確認できます。
    再生中のCtrl+Cで消音してメニューへ戻ることも確認してください。
  ・待機後のSTATUS/AUDIO、HOSTログ、曲の開始/終了、左右、歪み/音切れの有無を送ってください。
    2026-11-14、alpha.4で10分待機後もaudio_ready=1/fault=0、診断曲とYs II全曲完了、
    リピート・Ctrl+C消音/メニュー復帰、左右とも歪み/音切れなしをユーザー実機で確認済みです。
    全曲の完了ログは123137件・fault=0・gates=0・クリップ0、書込み開始遅延最大5301usでした。
    以下の再発時手順は将来の診断用として保持します。実施済み確認を繰り返す必要はありません。

もし再発した場合
  同じ試験を繰り返さず、STATUS/AUDIO/FAILとTXFAULT/TXFAULT_DMAを保存してください。
  TXFAULT reason=1は次のPCMを待つ間に対象DMAが再開、reason=2は両TX DMAが停止した状態です。
  produced/consumed/pending、FIFO、RX経過時間、分周値とDMA残件数を、停止処理前に保存します。
  音声faultは再起動が必要です。異常時はready=0も表示し、再生不能を明確にします。

検証
  自動テスト115件、既存の再起動160回、分周余りの累積一致、独立時計の10分モデル6条件、
  真のDMA停止時のfault5/診断保存、元のfault16停止、全曲I2CモデルとHOSTプレーヤーの試験を実施。
  実機の長時間安定性を、このモデル試験だけで保証するものではありません。
