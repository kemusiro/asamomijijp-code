# RCD1 — Rev CのローカルFM診断記録

alpha.4以降の調査用形式。再生用WYM1や公開I2Cプロトコルを変更しない。
生FMの24ビットを残し、復号前の波形・復号/補間後のPCMを比較する。
SSG、ライン出力、AMS-22のアナログ信号は録音しない。
このファイルだけでDAC以降が正常と証明したり、ポップ音の原因を確定したりしない。

`capture 31`は組み込みWYM1を先頭から1回実行し、31秒を過ぎて完全に含まれる
最初の625フレームのブロックから178ブロックをRAMへ記録する。
約2.0025秒を記録後、演奏を中止して全音を消す。通常の`play`は全曲再生を維持する。
開始秒は30～33だけを受理し、記録中はFMゲインの変更を拒否する。
途中STOP・通信断・FAULTで中断した記録は保存対象にしない。

## バイナリ

全432,150バイト。整数はlittle-endian。ヘッダーの予約領域と未使用トレース領域はゼロ。
この大きさを固定して、ホストがデバイスの指定する任意の大容量を割り当てないようにする。

| byte offset | 型 | 内容 |
| ---: | --- | --- |
| 0 | 4 bytes | ASCII `RCD1` |
| 4 | u32 | header bytes=96 |
| 8 | u32 | file bytes=432150 |
| 12 | u32 | 公称YMクロック=4000000Hz |
| 16 | u32 | 生フレーム周期のクロック数=72 |
| 20 | u32 | 入力ブロックのフレーム数=625 |
| 24 | u32 | 記録ブロック数=178 |
| 28 | u32 | 記録した生フレーム数=111250 |
| 32 | u32 | 有効なトレース件数、最大16384 |
| 36 | u32 | トレース開始オフセット=96 |
| 40 | u32 | 生データ開始オフセット=98400 |
| 44 | u32 | トレース1件のバイト数=6 |
| 48 | u32 | 生フレーム1件のバイト数=3 |
| 52 | u32 | 要求開始時刻µs、曲の演奏原点から |
| 56 | u32 | 最初の記録ブロックのDMA完了を観測した時刻µs、演奏原点から |
| 60 | u32 | 最後の記録ブロックのDMA完了を観測した時刻µs、演奏原点から |
| 64 | u32 | FMゲイン、8=100%、12=150%、上限16 |
| 68 | u32 | bus fast=1、slow=0 |
| 72 | u32 | 元WYM1全体のCRC32 |
| 76 | u32 | 元WYM1全体のイベント数 |
| 80 | u32 | flags、bit0=トレース容量超過（正常記録は0） |
| 84～95 | 12 bytes | 予約、ゼロ |

トレース領域は16384件×6バイトの固定領域。有効な件数だけを読む。
各レコードは`<IBB`で、`書き込み関数が成功して戻った時刻µs, register, value`。
先頭イベントから記録終了までを順に記録する。BUSY再試行は成功するまで含めない。
これはGPIOのWRエッジそのものの時刻ではなく、関数復帰直後のソフトウェア観測時刻。
停止後の全音OFF書き込みや、曲開始前の基板初期化はトレースに含まない。

生データ領域は111250件×3バイト。各値はPIOが取り込んだ24ビットをlittle-endianで保存する。
32ビット受信ワードのbits31..8を保存しており、最初の受信ビットは値のbit0に対応する。
現在の復号対象はbits23..11の13ビット（mantissa10、exponent3）。
先頭11ビットも保存しているため、取り込む位置・フレームのずれを後から調べられる。
先頭フレームの推定時刻はoffset56の値から11250µsを引く。
PIO FIFO、DMA、CPUで観測するまでの遅れがあるので、正確なワイヤのエッジ時刻ではない。

## USB転送

記録完了後の消音中だけ`dump`を受理する。転送中に演奏しない。
先頭は`DIAGBEGIN 432150 <8桁CRC32>`、次いで`DIAGDATA <最大128バイトのhex>`、
末尾は`DIAGEND`。各行はCRLF。CRC32はバイナリ全432150バイトのIEEE CRC32。
転送自体はRAM記録と分離し、再生中に大量のログを出さない。
10秒の期限、USB切断、改行以外の受信（STOP等）で転送を中止し、データの再保存は可能。
画面は明示的な保存クリック後だけ受理し、サイズ・CRC・magicを確認して`.rcd`を保存する。
失敗した転送ではファイルを保存しない。画面側の受信待ちは15秒で解除する。

## オフライン解析

標準Pythonだけで実行できる。出力先は未作成のローカル用ディレクトリを指定する。

```sh
python3 tools/analyze_capture.py revc-fm-diagnostic.rcd --out ../outputs/fm-capture-analysis
# 手元に同じ元データがある場合だけ、トレースの順序・実書き込み復帰遅延も検証：
python3 tools/analyze_capture.py revc-fm-diagnostic.rcd --out ../outputs/fm-capture-analysis-checked --song music/song.bin
```

`fm-wire.wav`は復号した生FM（無増幅、公称55556Hzへの整数丸め）。
`fm-pcm.wav`は実機C版と同じ625→540のブロック単位補間と固定ゲインを再現した48kHzのFM。
`analysis.json`は指数分布、ピーク、PCM飽和数、時刻等、`register-trace.json`は書き込み記録。
指数の非正規形や隣接サンプルの大きな差だけで異常とは断定しない。
どちらのWAVもアナログ出力の録音ではなく、時計の追従量や実アナログ波形の差は別途扱う。

記録・WAV・トレースは楽曲データを含む。手元の診断用として`local-test-data/`や`outputs/`等の
Git管理外へ置き、GitやGitHub Releaseへ追加しない。

## alpha.5の低遅延DMAとの互換性

ライブDMAは125入力→108出力となるが、生記録は5つの入力断片を625フレームの
論理ブロックへまとめる。178論理ブロック、111250フレーム、432150バイトは変わらない。
offset56は最初の5断片が完了した時刻、offset60は最後の断片が完了した時刻。
固定ゲインでは625→540変換と5回の125→108変換がビット一致するため、
従来の`analyze_capture.py`が出力するPCMも同じ。最初の完全な断片は要求開始後の
125フレームから取れるため、開始点の分解能だけ約11.25msから約2.25msへ変わる。
