YM2203 Rev C / USB-MIDI 6声・I2C切替の総合確認
2026-11-13 / firmware 0.2.0-alpha.1

実機結果
--------
2026-11-13、下記の総合確認についてユーザーから「確認できました」と報告あり。
初期受入確認を完了として記録する。HOST全ログ、OS名、期限超過回数は未提示のため、
個別の計測値やdeadline misses=0は推定しない。以下は実施した確認手順を保存したもの。

今回の変更
----------
USB-MIDI認識、FM/SSG音階、全音停止、左右正常、歪み/音切れなし、Thonny接続は
ユーザー実機で確認済み。6声とI2Cとの制御権切替を、1件にまとめて確認した。
Rev C側のファームウェア、GPIO、配線は前回と同じ。target/の再転送は不要。
今回追加したのは host/midi_handover.py とPC確認画面のボタン1/2/3。
USBケーブルの物理切断、OSごとの対応範囲、遅延測定、24時間運転はこの確認に含めない。

準備
----
・Rev Cは0.2.0-alpha.1のREADY状態にし、AMS-22と基板の音量を低くする。
・前回合格したI2C配線を使う。OTHER PicoのGP0=SDA、GP1=SCL、共通GND。
  ホスト側I2C0は10kHz、Rev C側はGP20/21、アドレス0x42。
・Thonnyの接続先はOTHER Picoにする。新しいhost/midi_handover.pyをPCから開く。
  以前保存した /lib/ym2203_revc.py はそのまま使える。まだRUNしない。
・以前のexample/endurance等は同時に実行しない。通常ライブラリの生成時にはSTOPが
  送られるため、この確認専用プログラムは既存MIDI演奏を止めずに接続する。
・更新後のpc/usb-midi-test.htmlをローカルサーバー経由で開き、再読み込みする。
  pcフォルダで python3 -m http.server 8765 --bind 127.0.0.1
  Windowsでpython3がない場合は py -m http.server に同じ引数を渡す。
  URL: http://127.0.0.1:8765/usb-midi-test.html
  「MIDI接続先を読み込む」→Rev CのMIDI出力ポートを明示的に選ぶ。

操作1：6声を聴いてからHOSTを開始
-------------------------------
1. ブラウザーの「1. 6声を順に確認して和音を保持」を押す。
   FM CH1=C4、CH2=E4、CH3=G4、SSG A=C3、B=E3、C=G3を順に発音し、
   その後6声の和音の発音要求を送る。各単独音と最後の和音を左右で確認する。
   ノート番号は順に60/64/67/48/52/55。初回は無音の準備時間が入る。
2. 「6声の発音要求を送信しました」と表示されたら、Thonnyへ移り、OTHER Picoで
   midi_handover.pyをRUNする。保持モードでは画面を移っても和音が継続する。
   HOSTはまずMIDI所有/全6声を読み取り、I2C書き込みがBUSYで拒否されることを確認。
   その間は和音が変化せず、その後I2C STOPで全音が止まり、4秒間無音になる。

操作2：I2C演奏中のMIDI入力
-------------------------
3. HOSTはI2CでFM3+SSG3声の固定和音を準備する。Thonnyに次が出るまで待つ。
       I2C PLAY /30 seconds of fixed six-voice chord
       NOW: browser button2 sends FM+SSG scales ...
4. この30秒の前半にブラウザーへ移り「2. I2C中へFM・SSG音階を送信」を1回押す。
   約14秒でFM/SSG各9音のMIDI送信が終わる。I2Cが制御中なので旋律は聞こえず、
   I2Cの固定和音が持続するのが正常。画面に送信終了が表示されたことも確認する。
   I2C PLAYの表示前には押さない。30秒終了直前にも押さない。
   途中で別画面へ移ると、この通常モードの音階送信は中止される。
5. 約30秒後にHOSTのSTOPで和音が止まり、さらに4秒間無音になる。
   待機中に、先ほど破棄されたMIDI音階が自動で鳴り始めないことを確認する。

操作3：明示的なMIDI再開と最終停止
--------------------------------
6. Thonnyの次の表示を確認してからブラウザーのボタン3を押す。
       WAIT FINAL MIDI / browser button3 sends six voices;within90s
   「3. 復帰確認用に6声を保持」で明示的な新規Note Onを送り、6声和音が再開する。
   HOSTが検出して約1.2秒待った後、I2C STOPで全音を止める。最終4秒間も無音。
7. 次の末尾を確認する。
       FINAL STATE result=0 flags=1 queued=0 midi_owner=0 mask=0 usb=1
       HOST PASS: ...
       DONE: ...
   最後にブラウザーで「MIDI全音停止」を押し、画面の保持モードも解除する。
   正常終了時、Rev CはREADYのまま継続稼働する。SAFEは停止時に出る表示なので、
   このHOST確認の終了時にRev C側でSAFEが出る必要はない。

保持モードと中断
----------------
ボタン1/3の和音保持だけは、Thonnyへの切替を可能にするため別画面でも継続する。
保持開始から2分、MIDI全音停止、送信先/チャンネル変更、ページ終了で解除する。
通常の単音・音階・ボタン2は、画面を離れると停止する。
OSやブラウザーが停止/休止した場合に、タイマーや終了時送信の実行は保証できない。
HOST待機は最大90秒。間に合わなければ例外になり、既知のRev CにはSTOPを送って終了する。
途中でHOSTをCtrl+Cした場合もSTOPを送る。必要ならブラウザーのMIDI全音停止、
またはRev CをCtrl+CしてSAFEを確認する。再試行はボタン1から始める。

報告する内容
------------
・最初の6単独音と和音、I2C書き込み拒否中の和音持続。
・ボタン2の送信完了表示と、その間I2C固定和音が変化しなかったこと。
・ボタン3での和音再開と、計3回のSTOP後の各4秒無音。
・左右、歪み、予定外の音切れ、気になるクリック音。
・HOSTログ全体（失敗した場合も末尾の例外まで）。

検証範囲
--------
HOSTが読むMIDI所有/声マスクはファームウェアの状態であり、アナログ音の測定ではない。
またHOSTは、ボタン2のMIDIが実際にPCから送られたか、USBに届いたかを観測しない。
HOST PASSだけで「I2C中のMIDI入力を実機確認した」とは判断せず、画面と聴取結果を併記する。
自動テストは実際のHOST/プロトコル/MIDI処理を模擬USB・GPIO・時刻で検証したもの。
実機6声と制御権切替は、冒頭のユーザー確認報告に基づいて合格と記録する。
自動テスト結果と実機確認報告は区別し、未提示のログ値は補完しない。
