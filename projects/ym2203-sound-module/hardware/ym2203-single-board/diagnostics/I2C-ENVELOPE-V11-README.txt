2. 音と状態
-----------
各区間は約2秒です。
  1 持続音
  2 キーオフ: 短い収まりの後に消音、DAC/LINEは有効のまま
  3 持続音の再発音
  STOP・1秒待機・減衰設定（出力は閉じたまま、設定完了待ちが加わる）
  4 減衰音1: キーオンのまま小さくなる
  5 キーオフ: DAC/LINEは有効のまま
  6 減衰音2: 再発音して同じように小さくなる
  STOP・1秒待機・持続設定（出力は閉じたまま）
  最後 短い持続音 -> 約1秒で自動消音

FM CH1・直列4オペレーター・約440Hz・キャリアTL64、モジュレーターTL40/MULTI1・SSG OFFは同じです。
持続DR0/SLRR0x0F、減衰DR12/SLRR0x8F、AR31/SR0/RR15を維持します。
減衰は小さくなることであり、キーオンのまま完全無音になる保証はありません。
速いRR15なので、キーオフ後に長い余韻が聞こえる必要はありません。
設定差分は8レジスタのままです。分割はSTOP中なので、途中の設定で音は出ません。

命令、状態6バイト、1秒リース、40ms応答待ち、1秒ACKタイムアウト、5分上限は従来と同じです。
  状態=[ACK,最後の命令,モード,期限フラグ,プリセット番号,キー状態]
保留中は前のACK/命令/プリセット番号を保持し、全8レジスタの成功後に一度だけACKを進めます。
書き込み途中の例外ではACK/選択を確定せず、共通終了処理で消音・停止します。
HOSTは再送せず、単一命令の完了を待ちます。ACKが変わる前に発音命令を重ねません。
任意のレジスタ書き込みや音色値、I2C高速化を追加するものではありません。

3. 追加ログと報告
-----------------
通常のLIVE I2CとSAFE/DONEに加え、キャプチャ停止後に次を表示します。
  ENVELOPE: updates=3 writes=24 max_write_us=... pending=-1 step=8
updates=3は持続 -> 減衰 -> 最終持続の設定完了回数、writes=24は分割した書き込み数です。
起動時の停止中設定はこのカウンターに含みません。
max_write_usは単一レジスタ処理の最大経過時間で、I2Cサービス全体のmax_poll_usとは別です。
pending=-1は保留なし、step=8は最後の設定の完了を示します。
失敗した場合も、停止後に途中のカウンターと保留命令が表示されます。

両側のログ全文、6区間の聞こえ方、左右、歪み/予定外の音切れ/クリック音、最後の自動消音を報告してください。
HOST PASS・HOST SAFE、Rev CのSAFE・DONE、deadline misses=0、lease_expirations=1を確認します。
HOSTのEXPECTED TARGET FINAL ACKとRev Cのcommands=を照合します。KEEP回数で値は変わり得ます。
共通案内のFM MIXER HOST / all nine sound sectionsは読み替え、専用envelope HOSTと6区間を使います。
失敗時はHOSTを再実行せず、Rev CもCtrl+Cで停止し、追加ENVELOPEログからSAFE・例外末尾まで保存します。

4. 検証と制約
-------------
修正前は、完了ACKの延期を要求する回帰テストが失敗しました。
レジスタ当たり2300us・I2Cサービス4000usの人工負荷モデルでも、元のネイティブ期限例外を再現しました。
この負荷は再現用に設定した値で、個々の実機書き込み時間の測定値ではありません。
修正後は同じモデルで3回のプリセット更新を終え、元の期限監視を維持して完走します。
1poll最大1書き込み、全8回後だけのACK、I2C読み取り中の保留、早すぎる次命令の拒否、
途中書き込み失敗、キーオフ時のゲート維持、期限消音、時刻周回、例外時の終了処理も確認します。
MicroPython WASMは模擬通信・時計・音源で全HOST手順を実行します。実音の減衰波形は合成しません。
自動検査は実機の音質、USB停止時間、GCや周辺回路の最悪時間を保証しません。
