1. 接続とファイル
-----------------
配線・給電は前回合格したままです。
  Rev C JHOST1 GND -> HOST Pico GND
  Rev C JHOST2 SDA -> HOST GP0（物理1番）
  Rev C JHOST3 SCL -> HOST GP1（物理2番）
3.3V I2C、0x42、10kHzハードウェアI2C0、既存4.7kΩプルアップです。
電源線同士はつなぎません。配線変更は両側電源OFF、試験中は両側に給電します。
JLINE -> AMS-22 LINE IN、ヘッドホン -> AMS-22、両音量低めから調整します。
AMS-22は別バッテリー、PC USBを外し、DIRECT MONITOR ON、LOOPBACK OFFです。

以前の一式を残し、各Picoの最上位へ次の2ファイルを追加してください。
  Rev C: target/rev_c_i2c_envelope_target.py
  HOST:  host/rev_c_i2c_envelope_host.py
ターゲットは既存のrev_c_i2c_timbre_target.pyとrev_c_fm_timbre_check.pyを使い、
HOSTはrev_c_i2c_timbre_host.pyを使います。既存ファイルを消さないでください。
未保存の場合はZIPのtarget/全14ファイルをRev C、host/全7ファイルをHOSTへ保存します。
今回は使わないcombined/pitch関連のファイルはZIPに含めませんが、Pico内には残せます。
既存ソースの更新は不要です。main.py / boot.pyには保存せず、UF2更新もしません。

2. 実行
-------
1) 両側を停止し、上の新しい2ファイルを保存します。
2) 両Pico USBとJPOWERを外して5秒待ち、JPOWER -> 両USBの順に接続します。
3) 各ThonnyをそれぞれのPicoへ再接続します。
4) Rev C側で rev_c_i2c_envelope_target.py を実行します。
   YM2203 Rev C / staged I2C FM envelope target v1
5) PHASE 0 READY後、HOSTで rev_c_i2c_envelope_host.py を実行します。
   YM2203 Rev C / I2C FM envelope HOST v1 / OTHER Pico only
6) 従来の6段階無音検査、専用シグネチャ、START/KEEP確認後、5秒待って発音します。
準備を含め約2分が目安です。combinedのファイルを起動する試験ではありません。

3. 聞こえる音（6区間と最後の自動消音）
-------------------------------------
各区間は約2秒です。
  1 SUSTAIN    一定の大きさでFMが鳴り続ける
  2 KEY OFF    短い収まりの後、テスト音が消える。DAC/LINEは有効なまま
  3 RETRIGGER  同じ持続音が再び鳴る
  STOP         1秒待機。出力を閉じたまま次の減衰設定を送る
  4 DECAY 1    発音直後から音が小さくなる。キーはオンのまま
  5 KEY OFF    テスト音が収まる。DAC/LINEは有効なまま
  6 DECAY 2    再発音して、区間4と同じように音が小さくなる
  STOP         1秒待機。出力を閉じたまま持続音へ戻す
  最後         持続音を短く鳴らし、約1秒で自動消音して終了

区間2/5のキーオフとSTOPは異なります。
キーオフでは音源だけをリリースし、DACとライン出力、FM受信・変換を継続します。
STOPではキーを解除したうえでDAC/LINEも閉じます。
今回は速いリリース設定なので、キーオフ後に長い余韻が聞こえる必要はありません。
減衰設定は音が小さくなるもので、キーオンのまま完全な無音になる保証はありません。
小さな背景のサー音とは分けて、テスト音の減衰・停止・再発音を判断してください。

初期設定やプリセット変更はSTOP中に行います。区間の時間には通信・確認時間が含まれます。
I2S遅延などもあるため、固定テンポや正確なアタック時間の測定ではありません。

4. 診断用のI2C命令
------------------
正式APIではありません。任意のレジスタ値や任意のエンベロープは公開しません。
起動6段階は従来のRCISO01!、その後の専用シグネチャはRCENV01!です。
旧ターゲットとの組み違いはHOSTが発音前に拒否します。
転送形式は従来どおり [0x20, 命令1byte]です。
  0 STOP、1 FM、6 KEEP、7 FINISH、8 START は従来と同じ
  0x30 KEY ON    キーオフ済みのFMを再発音（CH1全4オペレーター）
  0x31 KEY OFF   FMのキーだけを解除（出力ゲートを維持）
  0x80 SUSTAIN   持続プリセット
  0x81 DECAY     減衰プリセット
音程やTL/MULTI変更、SSG、合成モード等の他命令は受け付けません。
新命令はSTART完了後、期限フラグ0の場合だけ受理します。
プリセット変更はSTOP中だけ、KEY ON/OFFはFMモード中の反対のキー状態からだけ受理します。
FMモードを重ねて送っても、KEY OFFで解除したキーは再発音しません。再発音にはKEY ONを使います。

持続と減衰の差分は、4オペレーターのDRとSL/RRの計8レジスタです。
  持続: DR=0、SL/RR=0x0F
  減衰: DR=12、SL/RR=0x8F
AR=31、SR=0、RR=15、キャリアTL64、倍率、アルゴリズム、音程は変えません。
8回の書き込みは順番に行い、原子的な更新ではありません。
受信開始前には従来のserial音色へ設定してから、減衰差分を設定します。最初の選択番号は1です。
I2Cから差分を更新する際も、音源と出力はSTOP中で、連続FM変換と期限監視は継続しています。
書き込み途中の例外はACK/選択番号を確定せず、共通の消音・リセット処理で終了します。

0x10から6バイトの状態を読みます。
  [8bit ACK, 最後の命令, モード0/1, 期限フラグ, プリセット0/1, キー状態0/1]
プリセット番号は持続0、減衰1。キー状態は最後に指示した状態で、実際の音量やFMレジスタの読み戻しではありません。
減衰して小さくなってもキー状態は1です。KEY OFF後はモード1・キー0のままゲートが開いています。
KEEPはこの状態でもリースを更新します。通信が途絶えると約1秒でゲートも閉じ、モード0・キー0になります。
期限切れ後のKEY ON/OFFやプリセット命令で再発音することはありません。

HOSTは命令と保持の前後に全6バイトを照合し、保持中は既存のKEEP/ACK処理を使います。
通信失敗時に同じ命令を自動再送せず、後続区間にも進みません。
GPIO、回路、ネイティブ変換、PIO/DMA、I2S、共通I2C受信、音量監視を維持します。
40ms応答待ち、1秒ACKタイムアウト、1秒リース、ターゲット5分上限も同じです。
8レジスタ更新を含め、処理が音声変換の期限を超えた場合は従来どおり消音・停止します。
