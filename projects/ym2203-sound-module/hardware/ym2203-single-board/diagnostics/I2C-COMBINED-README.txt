直前の実機結果と今回の目的
--------------------------
I2C音色診断の8区間は実機合格です。TL/MULTIによる音色変化と再発音を確認しました。
左右正常、歪み/音切れ/気になるクリック音なし、最後の自動消音とHOST PASS・SAFE・DONEも確認。
2671ブロック、ピーク992、最大変換1118us、期限超過0、max_poll_us=7338、max_idle_poll_us=379。
期限消音1回、stale flush 0、最終ACK124はHOST期待値と一致しました。
受信468=HOST全体1506-起動1038、送信946=3694-起動2748も整合しています。

今回はFMの5音固定音程と、合格済みのTL/MULTI設定を組み合わせます。
「ドレミファソファミレド」を異なる音色で4回演奏します。全36音、SSGは鳴らしません。
4回の間もキーを保持し、音階の境界でTL/MULTIを切り替えます。
新しいGPIO、任意レジスタ、音量設定、音色値、変換処理は追加しません。
組み合わせ診断v1は実機で4回とも音階/音色変化が正常、左右正常、歪み/音切れ/気になるクリック音なし。
最後の自動消音とHOST PASS・SAFE/DONEを確認。4109ブロック、最大変換1119us、期限超過0。
最終ACK165、期限消音1回、stale flush 0。受信722=1760-1038、送信2058=4806-2748も整合しました。
ただし、最初のCが長いとの報告があり、HOST v1.1で初期設定をSTOP中へ移して重複C設定を省きます。
修正手順と制約はNOTE-START-README.txt。配布済みv1 ZIPは変更しません。

1. 配線とファイル
-----------------
前回合格した配線・給電のままで行います。
  Rev C JHOST 1 GND -> HOST Pico GND（物理3番など）
  Rev C JHOST 2 SDA -> HOST GP0（物理1番）
  Rev C JHOST 3 SCL -> HOST GP1（物理2番）
3.3V I2C、0x42、10kHzハードウェアI2C0、既存4.7kΩプルアップです。
電源線同士はつなぎません。配線変更は両側OFF、試験中は両側を給電します。
JLINE -> AMS-22 LINE IN、ヘッドホン -> AMS-22。両方の音量を低めから調整します。
AMS-22は別バッテリー、PC USBを外し、DIRECT MONITOR ON、LOOPBACK OFFです。

前回のファイルを残して、以下だけを各Picoの最上位へ追加します。
  Rev C: target/rev_c_i2c_combined_target.py
  HOST:  host/rev_c_i2c_combined_host.py
今回のターゲットはrev_c_i2c_timbre_target.pyを、HOSTはrev_c_i2c_timbre_host.pyをimportします。
前回の2ファイルも必ずPico内に残してください。既存19ファイルは変更していません。
未保存の場合はtarget/内全14ファイルをRev C、host/内全7ファイルをHOSTへ保存してください。
main.py / boot.pyへは保存しません。UF2更新は不要です。

2. 実行
-------
1) 両側を停止して上の新しい2ファイルを保存します。
2) 両Pico USBとJPOWERを外して5秒待ち、JPOWER -> 両Pico USBの順に接続します。
3) 各ThonnyをそれぞれのPicoへ再接続します。
4) Rev Cで rev_c_i2c_combined_target.py を実行します。
   YM2203 Rev C / staged I2C combined FM pitch + timbre target v1
5) PHASE 0 READY が出たら、HOSTで rev_c_i2c_combined_host.py を実行します。
   YM2203 Rev C / I2C combined FM pitch + timbre HOST v1 / OTHER Pico only
6) 6段階の無音検査、専用シグネチャ・START/KEEP確認後、5秒待って発音します。
準備を含め約2分です。従来のtimbre_target.py / timbre_host.pyを起動する試験ではありません。

3. 聞こえる音
-------------
次の音階を、異なる4通りの音色で演奏します。
  ドレミファソファミレド（C4 D4 E4 F4 G4 F4 E4 D4 C4）
  1回目: TL96、MULTI1   弱い変調
  2回目: TL40、MULTI1   強めの変調
  3回目: TL40、MULTI2   モジュレーター倍率を変える
  4回目: TL40、MULTI3   さらに倍率を変える

キーオンは最初の1回だけです。音符の間にも音階の間にも意図的な無音はありません。
1回目の最後のドと2回目の最初のドなどは、同じ高さの音を保ったまま音色が変わります。
音階の境界はHOSTのSCALE 1/4 ... 4/4表示と合わせて確認してください。
4回目終了後はSTOPで1秒無音、その後、最後の音色のドを約1秒鳴らして自動消音します。

キャリアTL64、キャリアMULTI1、直列4オペレーターの設定は前回と同じです。
TLが小さいほど変調が強くなりますが、聴感上の音量や音程感が同じになる保証はありません。
FMの設定音程は約261.5/293.7/329.8/349.3/392.1Hzです。
音色と音程は別々のI2C命令で順に更新します。3モジュレーターやFM音程2バイトの更新も原子的ではありません。
通信時間やI2Sバッファ遅延を含むため、厳密なテンポや同時刻の音色/音程変更の試験ではありません。
予定外の無音、歪み、気になるクリック音がないか確認してください。

4. 診断用I2C拡張
----------------
正式APIではありません。従来の音色ターゲットを継承し、5音の音程命令だけを追加します。
起動6段階のRCISO01!は同じ、その後は専用シグネチャRCCMB01!です。
旧音色ターゲットRCTIM01!等との組み違いはHOSTが発音前に拒否します。
書き込みは従来どおり [0x20, 命令1byte]です。
  0 STOP、1 FM、6 KEEP、7 FINISH、8 START は従来と同じ
  0x40..0x44  FM CH1のC4/D4/E4/F4/G4
  0x60..0x63  モジュレーターTL96/64/40/24
  0x70..0x72  モジュレーターMULTI1/2/3
SSG、合成/独立ミュートのモード2..5、任意レジスタや範囲外の値は受け付けません。
音程/音色命令はSTART完了後、期限切れフラグ0、STOP中またはFM単独発音中だけ受理します。
命令で発音ゲートを開いたり、期限切れを解消して再発音したりしません。
発音中に受理した場合は1秒リースを更新します。KEEPと期限消音も従来と同じです。

0x10から7バイトを読みます。
  [8bit ACK, 最後の命令, モード0/1, 期限フラグ, TL番号0..3, MULTI番号0..2, 音程番号0..4/255]
初期選択は[2,0,255]、最終選択は[2,2,0]です。255はまだ音程を選択していない状態です。
STOPや期限消音で設定記録は消しません。FMレジスタを読み戻した値ではありません。
HOSTは各変更の前後と各KEEP後に全7バイトを照合します。
各音で200ms待機+KEEPを2回行い、各ACK確認には従来の40ms待機を使います。
通信エラーや不一致時は命令を自動再送せず、後続音も送りません。
複数レジスタの途中書き込み失敗ではACK/設定記録を確定せず、共通終了処理で消音・リセットします。
1秒リース、1秒ACKタイムアウト、5分ターゲット上限、ネイティブ変換の期限・音量監視は維持します。

5. 結果の報告
-------------
両側のログ全文と、4回とも音階が分かること、音階間での音色変化、左右、
歪み/予定外の音切れ/クリック音、最後のSTOP無音と短い音の自動消音を報告してください。
HOST PASS、HOST SAFE、Rev CのSAFE・DONE、deadline misses=0を確認します。
EXPECTED TARGET FINAL ACKとRev Cのcommands=は一致します（8bitの値で、累計ではありません）。
lease_expirations=1は最後の意図的な消音です。
共通Rev Cの案内にFM MIXER HOST / all nine sound sectionsと出ても、専用combined HOSTと4音階を使います。

失敗時はHOSTを再実行せず、Rev CもCtrl+Cで停止し、LIVE I2CからSAFE・例外末尾まで保存してください。
両側を初期化してから再試験します。
