5音のプリセット命令だけを追加します。任意レジスタ書き込み、音色編集、予約演奏は追加しません。

1. 接続とファイル転送
---------------------
前回合格した配線・給電を維持します。
  Rev C JHOST 1 GND -> HOST Pico GND（物理3番など）
  Rev C JHOST 2 SDA -> HOST GP0（物理1番）
  Rev C JHOST 3 SCL -> HOST GP1（物理2番）
電源線同士はつながず、配線変更時は両側OFFにします。両側を給電して試験します。
3.3V I2C、0x42、10kHzハードウェアI2C0、既存4.7kΩプルアップです。
JLINE -> AMS-22 LINE IN、ヘッドホン -> AMS-22、両方の音量を低くします。
AMS-22は別バッテリー給電、PC USBを外し、DIRECT MONITOR ON、LOOPBACK OFFです。

前回の一式が両Pico内に保存済みなら、次の3ファイルだけを更新/追加します。
  Rev C: target/rev_c_i2c_fm_target.py    更新（診断用ターゲットの差し替え引数を追加）
         target/rev_c_i2c_pitch_target.py 追加（今回実行するファイル）
  HOST:  host/rev_c_i2c_pitch_host.py     追加（今回実行するファイル）
各Picoの最上位へ保存します。main.py / boot.pyには保存しません。UF2更新は不要です。
未保存の場合は、ZIPのtarget/内全12ファイルをRev C、host/内全6ファイルをHOSTへ保存してください。
過去のendurance/cycle HOSTは今回importしないためZIPには含めません。Pico内に残っていても構いません。
共通ファイル更新後は両側を再起動し、Thonnyのimportキャッシュもリセットします。

2. 実行手順
-----------
1) 両側を停止し、上の3ファイルを保存します。
2) 両Pico USBとJPOWERを外して5秒待ち、JPOWER -> 両Pico USBの順に接続します。
3) 各ThonnyをそれぞれのPicoへ再接続します。
4) Rev C側で rev_c_i2c_pitch_target.py を実行します。
   YM2203 Rev C / staged I2C FM + SSG pitch target v1
5) PHASE 0 READY が出たら、HOST側で rev_c_i2c_pitch_host.py を実行します。
   YM2203 Rev C / I2C FM + SSG pitch HOST v1 / OTHER Pico only
6) 6段階の無音検査、専用シグネチャ・START/KEEP確認後、5秒待って音階を自動演奏します。
準備を含め約2分が目安です。従来のstaged_target.py / cycle_host.pyを実行する試験ではありません。

3. 聞こえる音
-------------
  FMだけ:  ドレミファソファミレド -> 1秒無音 -> ドレミファソファミレド -> 1秒無音
  SSGだけ: ドレミファソファミレド -> 1秒無音 -> ドレミファソファミレド -> 1秒無音
  最後:    SSGのドを約1秒 -> 自動消音 -> 終了

各音階はC4-D4-E4-F4-G4-F4-E4-D4-C4、計4音階・36音です。
音符ごとにキーオフをせず、発音を保って音程を変えます。各音の間に意図的な無音はありません。
FMとSSGの音色差を確認してください。音程はほぼ同じ範囲ですが、量子化による差があります。
  FM: 約261.5 / 293.7 / 329.8 / 349.3 / 392.1 Hz（従来のFMプリセット）
  SSG: 261.51 / 293.43 / 328.95 / 349.16 / 393.08 Hz（4MHz、周期239/213/190/179/159）
通信時間を含むため1音は厳密なテンポではありません。これはリアルタイム音程変更の診断です。
FMはA4→A0、SSGは周期下位→上位を書きます。複数レジスタの更新は原子的ではありません。
I2SバッファによるFMの遅れもあります。予定外の途切れ、歪み、気になるクリック音を報告してください。

4. 診断専用I2C拡張（正式APIではありません）
------------------------------------------
転送形式は従来と同じ [0x20, 命令1byte]。ポインタ書き込みだけでは発音しません。
起動6段階は従来のRCISO01!、その後の制御シグネチャは専用のRCPIT01!です。
従来ターゲットRCMIX02!と組み違えた場合、HOSTは音を出す前に不一致で停止します。
  0x00..0x08: 従来のSTOP、FM、SSG、BOTH、DAC/LINE MUTE、KEEP、FINISH、START
  0x40..0x44: FM CH1のC4/D4/E4/F4/G4を選択
  0x50..0x54: SSG AのC4/D4/E4/F4/G4を選択
新しい音程命令は、START完了後のSTOP中または対応する単独発音モード中だけ受理します。
期限切れ後や別音源/合成モードでの音程命令、範囲外命令は例外となり、外側の終了処理で消音します。
音程命令自体は発音ゲートを開きません。発音中の受理は1秒リースを更新します。
更新失敗時はACK/選択状態を確定せず、例外で停止します。
SSGは周期2レジスタを書いて読み戻し、FMは従来の5音固定A4/A0書き込みをそのまま利用します。
音量、キー操作、I2S、PIO/DMA、ネイティブ変換、期限監視の処理は従来と同じです。

状態0x10..0x15を6バイトで読みます。
  [8bit ACK, 最後の命令, モード, 期限消音フラグ, FM選択番号, SSG選択番号]
選択番号は0..4、まだ選択していなければ255です。STOPや期限消音で選択値は消しません。
FM選択値はソフトウェアの設定記録であり、YMのFMレジスタを読み戻した値ではありません。
HOSTは音程命令と各KEEP後に全6バイトを照合します。各音で200ms待機とKEEPを2回行います。
期限消音や不一致を検出したら後続音を送らず、同じ命令を自動再送しません。

5. 報告と検証範囲
-----------------
両側のログ全文と、FM・SSG各2回の音階、左右、音程変化、歪み/途切れ/クリック音、
各音階後の1秒無音、最後の約1秒発音と自動消音を報告してください。
期待する末尾はHOST PASS、HOST SAFE、Rev CのSAFE・DONE、deadline misses=0です。
HOSTのEXPECTED TARGET FINAL ACKとRev Cのcommands=が一致します（8bit、累計ではありません）。
lease_expirations=1は最後の意図的な自動消音です。選択番号は最終的に両方0です。
共通Rev CメッセージのFM MIXER HOST / all nine sound sectionsは過去の共通案内です。
今回実行するのは専用pitch HOST、聞き取り対象は4音階・36音と最後の短いSSG音です。

失敗時はHOSTを再実行せず、Rev CもCtrl+Cで停止してLIVE I2CからSAFE・例外末尾まで保存します。
配線を変えず両側を初期化してから再試験します。

PCのテストで、独立した11.25ms受信モデルによる36音の順序、実際のバス操作の書き込み値、
状態照合、最終期限消音、誤シグネチャ、開始前/期限切れ/別モードの命令拒否を検査します。
SSG読み戻し不一致、通信例外時の再送なし、変換期限超過/MemoryError/Ctrl+C時の終了処理も検査します。
MicroPython WASMでは全HOST手順を模擬通信・時計・音源で実行し、Arm向けmpy-crossでもコンパイルします。
これらは実機の音、PIO/DMA/I2S/I2Cやアナログ信号の検証を代替しません。
I2C高速化、音色のI2C編集、6音同時制御、予約演奏、長時間運転、USB-MIDIは今回の対象外です。
