1. 接続とファイル
-----------------
前回合格した配線・給電のままで行います。
  Rev C JHOST 1 GND -> HOST Pico GND（物理3番など）
  Rev C JHOST 2 SDA -> HOST GP0（物理1番）
  Rev C JHOST 3 SCL -> HOST GP1（物理2番）
3.3V I2C、0x42、10kHzハードウェアI2C0、既存4.7kΩプルアップです。
電源線同士はつなぎません。配線変更は両側電源OFF、試験中は両側を給電します。
JLINE -> AMS-22 LINE IN、ヘッドホン -> AMS-22、両方の音量を低めにします。
AMS-22は別バッテリー、PC USBを外し、DIRECT MONITOR ON、LOOPBACK OFFとします。

前回のファイルはそのまま残して、以下を各Picoの最上位へ保存します。
  Rev C: target/rev_c_fm_timbre_check.py   ローカル試験で使った共通ヘルパー
         target/rev_c_i2c_timbre_target.py 今回追加・実行するファイル
  HOST:  host/rev_c_i2c_timbre_host.py     今回追加・実行するファイル
ヘルパーが保存済みなら同じ内容で置き換えて構いません。
前回の音程診断から既存ソースは一切変更していません。
未保存の場合はtarget/全13ファイルをRev C、host/全6ファイルをHOSTの最上位へ保存します。
main.py / boot.pyには保存しません。UF2の更新は不要です。
pitch_target.py / pitch_host.pyは今回importしないためZIPには含めません。Pico内に残せます。

2. 実行
-------
1) 両側を停止して上のファイルを保存します。
2) 両Pico USBとJPOWERを外して5秒待ち、JPOWER -> 両Pico USBの順に接続します。
3) 各ThonnyをそれぞれのPicoへ再接続します。
4) Rev C側で rev_c_i2c_timbre_target.py を実行します。
   YM2203 Rev C / staged I2C live FM timbre target v1
5) PHASE 0 READY が表示されたら、HOST側で rev_c_i2c_timbre_host.py を実行します。
   YM2203 Rev C / I2C live FM timbre HOST v1 / OTHER Pico only
6) 6段階の無音検査と専用シグネチャ・START/KEEP確認後、5秒待って発音します。
準備を含め約2分が目安です。従来のpitchファイルやstaged_target.pyを起動する試験ではありません。

3. 聞こえ方
-----------
各区間は約2秒です。区間1から7まではキーを保持し、意図的な無音を挟みません。
  1 TL=96    弱い変調。基準として聞く
  2 TL=64    変調を強める
  3 TL=40    さらに強める
  4 TL=24    今回の中で最も強い変調
  5 MULTI=1  TLを40へ戻し、倍音の比較を開始
  6 MULTI=2  モジュレーターの周波数倍率を変える
  7 MULTI=3  さらに倍率を変える
  STOP       1秒無音
  8 再発音   TL=40、MULTI=1に戻して約2秒鳴らす
  STOP       1秒無音
  最後       同じFMを短く鳴らし、約1秒で自動消音して終了

TLは小さいほど変調が強くなります。音量が一定という意味ではなく、音色や感じる大きさが変わります。
MULTI変更中もキャリアは倍率1のままで、基本の設定周波数は約440Hzです。
強い変調では倍音の聞こえ方が変わるため、音階試験のような音程の変化とは区別してください。
3オペレーターの設定は順に書き込みます。更新は原子的ではなく、FM/I2Sの出力遅延もあります。
各区間での音色の変化と、予定外の無音、歪み、気になるクリック音がないかを確認します。
計画されたSTOPの無音と最後の自動消音は正常です。小さな背景のサー音とは分けて判断します。

4. 診断専用のI2C命令と状態
--------------------------
正式な音源APIではありません。任意レジスタ書き込みや任意の音量値は受け付けません。
GPIO・回路・ネイティブ変換・PIO/DMA・I2S・期限監視・1秒リース・40ms HOST待機は維持します。
全4オペレーターの初期設定は、6段階起動の最終段階で受信停止・LINE/DACミュートのまま行います。
従来の1オペレーター事前検査はその前に同じ内容で実行します。
共通コントローラーのキーオン0x10を、この専用バス内でCH1全4オペレーターの0xF0へ変換します。

起動6段階はRCISO01!、その後の専用シグネチャはRCTIM01!です。
旧ターゲットRCPIT01! / RCMIX02!との組み違いは、HOSTが発音前に拒否します。
書き込みは従来どおり [0x20, 命令1byte]、ポインタだけでは発音しません。
  0 STOP、1 FM、6 KEEP、7 FINISH、8 START は従来と同じ
  0x60..0x63  モジュレーターTL=96/64/40/24
  0x70..0x72  モジュレーターMULTI=1/2/3
この試験ではSSG、合成、独立ミュートのモード2..5と、音程命令は受け付けません。
音色命令はSTART完了後、期限切れフラグ0、STOP中またはFM単独発音中だけ受理します。
音色命令で発音ゲートを開いたり、期限切れを解消して再発音したりしません。
発音中の受理はリースを更新し、STOP中は選択値だけを変更します。
範囲外命令、期限切れ、例外、ネイティブ変換の期限超過は、外側の終了処理で消音します。

0x10から6バイトの状態を読みます。
  [8bit ACK, 最後の命令, モード0/1, 期限フラグ, TL選択番号0..3, MULTI選択番号0..2]
初期選択はTL40=番号2、MULTI1=番号0、最後も[2,0]です。
選択番号はソフトウェアの設定記録です。YMのFMレジスタを読み戻した値ではありません。
HOSTは各変更の前後と保持後に状態を確認し、保持中は既存のKEEP/ACK処理を使います。
3レジスタの途中で書き込みが失敗した場合、ACKと選択番号を確定せず例外で終了します。
すでに書いたレジスタは巻き戻せないため、共通の消音・リセット処理で終了します。
通信失敗時は同じ音色命令を自動再送せず、後続区間にも進みません。

-----------------

失敗時はHOSTを再実行せず、Rev CもCtrl+Cで停止し、LIVE I2CからSAFE・例外末尾まで保存します。
