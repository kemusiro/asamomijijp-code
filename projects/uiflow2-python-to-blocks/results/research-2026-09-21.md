## 一次資料の静的確認

API仕様の一次資料として、M5Stack公式`uiflow-micropython`のタグ[`2.5.3`](https://github.com/m5stack/uiflow-micropython/tree/2.5.3)、コミット[`50e440780492aa847378c7d3477ab912f7063bac`](https://github.com/m5stack/uiflow-micropython/commit/50e440780492aa847378c7d3477ab912f7063bac)を固定した。対象ファイルのSHA-256と抽出仕様は`profile.json`、詳しい判定境界は`docs/official-uiflow-micropython-2.5.3.md`へ記録した。

公式RGBドライバー`m5stack/libs/unit/rgb.py`では、実行時クラスが`RGBUnit(SK6812)`であり、コンストラクターがポート配列の2番目をSK6812のデータGPIOへ渡す。公式の`rgb_core.m5f2`／`rgb_core.py`対では、`portType=B`と`RGBUnit((36, 26), 3)`、次の対応を確認した。

| 公式ブロック型 | Python API |
| --- | --- |
| `unit_rgb_set_brightness` | `set_brightness(0..100)` |
| `unit_rgb_set_fill_color` | `fill_color(RGB888)` |
| `unit_rgb_set_index_color` | `set_color(index, RGB888)` |

公式例の標準接続はPORT.Bである。今回のプロファイルはCore2 v1.3本体側面へ接続したPORT.Aを対象とし、V2.5.3 Web IDEが生成した`RGBUnit((33, 32), 3)`と実機動作を別途確認している。

公式リポジトリにはWeb IDEのBlockly定義、Python生成器、`.m5f2`の完全なスキーマは見当たらなかった。また、タグ`2.5.3`の公式RGB `.m5f2`は内部が`version=V2.0`で`versionNumber`を持たない。したがって、公式例はAPIとブロック対応の根拠に使い、V2.5.3の保存形式、Core2初期化、PORT.A設定は今回Web IDEから採取したfixtureと往復結果を根拠にする。

補助調査として、公式StickS3音声サンプルも2026-09-21に静的解析した。取得時の`versionNumber`はV2.4.1で、`blockly`は複数の最上位要素を連結したXML断片だった。機種と版が異なるためCore2のひな形には使わず、全文も本プロジェクトへ複製していない。

## 対応表（この採取条件で確認済み）

| 対象 | 保存XML/JSON | 生成Pythonまたは観察 |
| --- | --- | --- |
| Setup | basic_on_setup / statement FUNC | def setup() |
| Loop | basic_on_loop / statement FUNC | def loop() |
| 初期化 | system_m5_begin | M5.begin() とUI初期化など。1ブロック対1行ではない |
| 周期更新 | system_m5_update | M5.update() |
| 待機 | time_sleep_second / value SECOND / shadow math_number / field NUM | time.sleep(整数) |
| 数値制約の記録 | shadow内mutation max=Infinity,min=0,precision=0 | Sleepの採取例。一般的意味と全境界値は未検証 |
| RGB初期化 | unit_rgb_init / field NAME / value NUMBER | rgb_0 = RGBUnit((36,26),3) |
| RGB全色指定 | unit_rgb_set_fill_color / NAME=rgb_0 / value COLOR | rgb_0.fill_color(0xff0000) |
| 色入力 | block color_rgb_palette / mutation mode=palette / MODE=palette / COLOR=#ff0000 | 整数RGB888リテラルへ生成 |
| 呼び出し順 | next/block | 同じ本体内の順次実行 |
| Setup状態 | mutation isBegin=true / UPDATEOP=true | 初期化有効状態。切り替え差分は未検証 |
| Loop状態 | mutation isUpdate=true / UPDATEOP=true | 更新有効状態。切り替え差分は未検証 |
| Unit設定 | units[].type=unit_rgb, name=rgb_0, portType=B, initBlockId | initBlockIdと初期化block id一致 |
| userPort | [22,21] | 生成コードは(36,26)。この配列を実配線とみなしてはならない |
| その他JSON | components,resources,screen,hats等 | 変換器はそのまま継承。全フィールドの仕様は未解明 |

portTypeによる既定ピン選択とCustom用userPortが別である可能性はあるが、これは推測。
PORT.BからPORT.Aへ`portType`を変更すると、UiFlow2 V2.5.3の生成コードは`RGBUnit((36, 26), 3)`から`RGBUnit((33, 32), 3)`へ変化した。外側JSONの`userPort`は`[22, 21]`のままだったため、既定ポートでは`portType`が優先されると観察できる。一般的な仕様かどうかは未確定。

## 方式比較と今回の決定

独自ラッパーは呼び出し名と引数を小さく固定できるが、ラッパー定義とUiFlow2生成APIの対応管理が増える。
今回は既存呼び出しtime.sleep / rgb_0.fill_colorのみを入力として採用。
初期化まで自由なPythonとして受け付けず、検証済みひな形が初期化を所有する方式。
入力のsetup/loopはその初期化後へ挿入する処理列を表す。全文Pythonの意味保存とは主張しない。

## 実機確認（2026-09-22）

1. 電源を切ったCore2 v1.3の本体側面PORT.AへM5STACK-U003を接続し、USBでPCへ接続した。
2. USB ID `1a86:55d4`のシリアル機器へ接続。起動トレースの`startup/core2/framework.py`とREPLバナー`M5STACK Core2 with ESP32(SPIRAM)`で対象を確認した。
